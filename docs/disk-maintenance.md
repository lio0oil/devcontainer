# 定期メンテナンス手順（VS Code のターミナルだけで行う）

Dev Container を使い続けると、キャッシュや古い VS Code サーバーが少しずつ溜まってディスクを圧迫する。
この手順は、**VS Code で接続したまま、VS Code のターミナルだけで**行うお手入れをまとめたもの。

- docker コマンドも、Windows の PowerShell も使わない。
- 普段使っているターミナル（`Ctrl+@` で開く）にコマンドを貼り付けるだけで進められる。
- 原因の調査や、vhdx を縮めて Windows のディスクを実際に空ける作業は [disk-cleanup.md](disk-cleanup.md) を参照。

## いつ行うか

| タイミング | 目安 |
| --- | --- |
| 定期 | 月に 1 回 |
| VS Code をアップデートしたあと | 古いサーバーが 1 つ増えるため |
| ディスクが気になったとき | 手順 1 で確認する |

## 実行する場所

接続しているコンテナ（または WSL）の **VS Code のターミナル**。
WSL に接続して使っている場合も、同じコマンドでよい。

## 手順 1: 今の状況を確認する

全体の使用量を見る。

```sh
df -h /
```

主な溜まり場所のサイズを見る。存在しないフォルダはエラーになるが、気にしなくてよい。

```sh
du -sh ~/.cache ~/.npm ~/.vscode-server ~/.local 2>/dev/null
```

## 手順 2: キャッシュを削除する

どれも、次に使うときに自動で作り直される。

uv のキャッシュを整理する。使われていない分だけを削除する穏やかな方法。

```sh
uv cache prune
```

全部削除したいときは、こちらを使う。

```sh
uv cache clean
```

npm のキャッシュを削除する。

```sh
npm cache clean --force
```

Homebrew の古い版とダウンロードキャッシュを削除する。

```sh
brew cleanup -s
```

apt のダウンロード済みパッケージを削除する。

```sh
sudo apt-get clean
```

> `uv cache clean` が「Cache is currently in-use」と表示することがある。他の uv プロセスの終了を待ってから実行されるので、そのまま待てばよい。

使っていなければ、次のキャッシュも削除してよい。大きいときだけで十分。

| 場所 | 内容 |
| --- | --- |
| `~/.cache/pyright-python` | pyright が使う Node 環境（約 0.4GB） |
| `~/.cache/ms-playwright-go` | Playwright のブラウザ（約 0.25GB） |
| `~/.cache/go-build` | Go のビルドキャッシュ |

```sh
rm -rf ~/.cache/pyright-python ~/.cache/ms-playwright-go
```

## 手順 3: 古い VS Code サーバーを削除する

VS Code は、更新のたびに新しいバージョンのサーバーを追加し、古いものを消さない。
1 バージョンあたり 0.2〜0.7GB で、数か月で数十 GB になる。

**今、接続に使っているサーバーを消すと、接続が切れる。** 先に、使用中のバージョンを確認して、それを残す。

### 3-1. 使用中のサーバーを確認する

使用中のサーバーの置き場所（`BIN`）と、バージョンのコミットID（`CUR`）を取り出す。

```sh
BIN=$(ps -eo args | grep -oE '[^ ]*/bin/(linux-x64/)?[0-9a-f]{40}' | head -1 | xargs -r dirname)
CUR=$(ps -eo args | grep -oE '[^ ]*/bin/(linux-x64/)?[0-9a-f]{40}' | head -1 | xargs -r basename)
echo "BIN=$BIN"
echo "CUR=$CUR"
```

**出力を必ず確認する。**

| 確認すること | 正しい例 |
| --- | --- |
| `BIN` が空でない | `BIN=.../vscode-server/bin/linux-x64` や `BIN=/home/ユーザー名/.vscode-server/bin` |
| `CUR` が 40 桁の英数字 | `CUR=6d62b1d5dace93a33b3a6d3eca1317bd5e15bcb1` |

どちらかが空のときは、**次の手順に進まない。** `ps -eo args` の出力から、`bin/` を含むパスを目で探して、手順 3-2 の `ls` で確認する。

### 3-2. 一覧を確認する

新しい順に並べる。`CUR` が含まれていることを確認する。

```sh
ls -1dt "$BIN"/*
```

### 3-3. 古いものを削除する

使用中のもの（`CUR`）は消さない。さらに、念のため、それ以外で一番新しい 1 個も残す。

```sh
[ -n "$BIN" ] && [ -n "$CUR" ] && ls -1dt "$BIN"/* | grep -v "$CUR" | tail -n +2 | xargs -r rm -rf
```

- `[ -n … ]` の部分は、`BIN` と `CUR` が空のときに何も実行しないための安全装置。外さない。
- 削除後に、もう一度 `ls -1dt "$BIN"/*` で、2 個だけ残っていることを確認する。

> `vscode` ボリュームは、Dev Containers を使うすべてのコンテナで共有される。他の devcontainer も同時に使っている場合は、そちらで使用中のバージョンも消えるおそれがある。他のコンテナの VS Code を閉じてから行う。

### 3-4. 拡張機能のダウンロードキャッシュを削除する

置き場所を探す。数秒かかることがある。

```sh
find / -maxdepth 5 -type d \( -name extensionsCache -o -name CachedExtensionVSIXs \) 2>/dev/null
```

見つかったフォルダの中身を削除する。`<見つかったパス>` は、上のコマンドの出力に置き換える。

```sh
rm -rf <見つかったパス>/*
```

## やってはいけないこと

| コマンド・操作 | 危険な理由 |
| --- | --- |
| `~/.vscode-server` や、サーバーの置き場所（`$BIN`）ごと削除する | 使用中のサーバーも消え、接続が切れる |
| `~/workspace` 以下の削除 | 作業ファイル。キャッシュではない |
| 変数（`$BIN` など）の内容を確認せずに `rm -rf "$BIN"/*` を実行する | `BIN` が空だと、`/*` が対象になり、システム全体を消すおそれがある |
| 手順 3 を、使用中のバージョンを確認せずに行う | 接続が切れる |
| `rm -rf ~/.cache` のように、キャッシュ全体を一括で消す | 動作中のツールの設定が壊れることがある |

## 終わったら

- 手順 1 のコマンドで、サイズが減ったかを確認する。
- **Windows のディスク（vhdx のファイルサイズ）は、ここまででは減らない。** コンテナの中でファイルを消しても、vhdx は自動では小さくならない。減らしたいときは、VS Code を閉じて、[disk-cleanup.md](disk-cleanup.md) の手順 5（コンパクト）を行う。
- 数か月に一度、コンパクトまで含めて実施するのが目安。
